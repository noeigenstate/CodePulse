# LumaDesk 核心能力整合

本轮以产品 `7a41eae`、独立固件 `7e3d9e6` 为基线。新增整合改动先在本地验证，
初始软件整合阶段不包含提交、推送、产品 main 合并、云端部署或刷机；后续用户授权的
真实文字联调和 2026-10-30 旧板刷写分别记录在文末。产品改动仅发布到
`codex/unified-product`，不合并产品 main；固件独立管理。

## 范围与来源

参考 LumaDesk 源码提交 `043efa33` 的产品规则和已实现接口：

- `xiaozhi-server-fork/lumadesk/reminders/`：单一持久化入口、30 分钟补报窗口、
  安静投递、稍后提醒；`plugins/`：创建/列出提醒、场景、长期记忆。
- `backend/app/providers/`：通义结构化计划、阿里语音识别和合成的 Provider 契约。
- 当前服务器配置采用 GLM `glm-4-flash`、FunASR 和 EdgeTTS。本轮 AI 默认沿用 GLM，
  语音先适配上面已有的阿里 NLS 契约；没有声称将 FunASR/EdgeTTS 服务打包进桌面。
- `xiaozhi-esp32-fork/main/audio/codecs/no_audio_codec.*`：独立 PDM 采集与 I2S 输出设计。

来源仓库：[LumaDesk](https://gitlab.com/libowen88/luma-desk)。代码按目标产品的
TypeScript/Electron 和 ESP-IDF 6.0.1 重新适配，不依赖原仓库路径或旧公网服务。
保留相关 Xiaozhi MIT 声明，见桌面的 `apps/desktop/THIRD-PARTY-NOTICES-ASSISTANT.txt`
和独立固件的 `THIRD-PARTY-NOTICES-AUDIO.txt`；桌面许可声明列入安装包资源。
不随源码复制原来的密钥、账号、会话、提醒数据库、设备身份或录音；用户明确授权的
本机凭据复用另行写入系统加密存储，见下方真实联调记录。

未迁入安卓、微信小程序、Java 管理后台、MQTT 网关、旧 OTA/账号绑定服务和学生产品。
自动唤醒词模型、常开麦克风和 AEC/VAD 不随本轮默认启用；语音链路使用明确开始/停止
的录音入口和新板独立讲话按键。后续若加入自动唤醒，需要单独验证模型分区、SDK 和功耗。

## 一个桌面后台

Electron 主进程承载待办数据库、提醒时钟、AI/ASR/TTS 适配、IPC 和设备接口，
与已有 StatusHub、HUD、设备服务共存。没有额外 Python 服务、云端服务器或生产监听端口。
现有工作状态、额度、已读和排序保持原模型；待办使用独立 `assistant.sqlite`，不迁移现有账户库。

桌面“待办与助手”提供：

- 手工创建、编辑、完成、取消待办，时间可选；事项及历史本机持久化。
- 自然语言建议，展示动作和准确时间，确认后才修改；确认重复提交不重复创建。
- 稍后提醒、安静时段、30 分钟补报及过期不补报；过期事项仍在待办列表。
- 场景与可查看/忘记的事实记忆；每次 AI 请求只带有界的相关上下文。
- 显式录音、转写、建议确认、手动朗读；页面隐藏或关闭即停止采集。
- 墨水屏临时展示 15 分钟，或通过“控制”选择固定/轮播待办，最多六行；紧急工作
  提醒仍优先。后续手动图片或便签会替换临时待办，不创建另一套永久显示开关。

普通待办离线可用；“10分钟后提醒我喝水”等明确表达可由本地规则形成建议。
其他 AI 请求默认 GLM `glm-4-flash`，也可选择通义 `qwen-plus` 或填写所选服务商支持
的模型名。语音识别/合成沿用阿里 NLS，输出为单声道
16 kHz signed 16-bit little-endian PCM。Provider 调用有超时、响应容量及音频时长限制。
没有配置服务时清楚报出缺失项，不用 mock 回答冒充 AI 或实际语音。

凭据只在系统加密存储可用时保存，界面只读取配置状态，不读回明文。也可通过显式
进程变量 `CODEPULSE_GLM_API_KEY`、`CODEPULSE_TONGYI_API_KEY`、
`CODEPULSE_ALIYUN_NLS_APPKEY`、`CODEPULSE_ALIYUN_NLS_TOKEN` 配置。
兼容的 `CODEPULSE_ASSISTANT_API_KEY` 仅绑定启动时所选 AI 服务商，不跨服务商发送。
界面先保存服务商设置，再保存它对应的凭据。NLS Token 过期需更新；本轮不迁入云端令牌服务。
录音在内存中处理，不默认写磁盘；发起识别会把本次语音发送到配置的阿里服务。
AI 请求还会发送当前输入、最多八条近期对话、前三十条未完成待办和前十条记忆；
不会采集桌面内容或编程任务正文。近期对话按桌面/设备隔离，30 分钟失效，退出清除。
播报后十分钟内，“稍后提醒”可以引用该设备最近的提醒；仍需用户确认，默认延后五分钟。

客户端退出或电脑休眠时不能保证到点提醒。桌面通知已请求投递不代表用户看到，
设备完成音频上传到 I2S 也不能代替真实扬声器发声验收。

## 设备接口和显示兼容

复用可选 17889 LAN 设备服务和现有设备 token；不通过 URL 传 token。
`/api/v1/device/assistant/*` 是新的、认证的助手专用端点，可生成建议、确认本设备建议
和获取语音。它们不会写 CLI 事件、确认编程任务或开放任意 shell/文件操作。
未注册该模块的设备服务仍保留原来只读行为。API 详情见配套设备协议补充。

待办列表通过 v1 的可选 `ambient.items` 扩展渲染，最多六项；每项包含 `title`、
`meta` 和 `overdue`。原 `ambient.text` 保留文字回退，旧固件忽略新字段仍能显示文字。
新固件将待办渲染为独立行、复选框和时间，不依赖 HTML/CSS 模拟实体屏。
两套桌面预览必须同步同一生产 C/Wasm 产物，并通过 native/Wasm 像素检查。
列表只在内容、到期里程碑或设置变化时改变；不渲染秒表，不增加周期清洁或红色驱动。

## 硬件兼容结论

| 项目       | LumaDesk Ding 板            | 当前 CodePulse Board1 / 新版要求                              |
| ---------- | --------------------------- | ------------------------------------------------------------- |
| 芯片与存储 | ESP32-S3 N16R8              | 同级基础具备；新板仍需确认实际料号                            |
| SDK        | 5.5.2                       | 保持 6.0.1，不整包替换固件或升级/降级 SDK                     |
| 屏幕       | 无                          | 保留 400×300 legacy 屏及低闪策略                              |
| 扬声器     | MAX98357A，I2S1             | 当前旧板只有蜂鸣器；新功放型号、供电和接线待核对              |
| 麦克风     | PDM，I2S0                   | 新板是否已布置 PDM 麦克风待确认；仅增加扬声器并不具备采音能力 |
| 音频引脚   | GPIO4/5/7/16，PDM17/6       | 与当前屏幕 BUSY/RST/CS/SCLK/MOSI/DC 重叠，不能照搬            |
| 电源、按键 | 与旧语音板的接法相关        | 保留 GPIO9 供电保持和现有电源键，讲话使用独立按键             |
| 电池采样   | GPIO1                       | 保留原 GPIO42 到 GPIO8 飞线和输入约束                         |
| USB        | GPIO19/20                   | 保留，禁止音频占用                                            |
| 分区       | 旧语音产品有独立模型/资源区 | 旧板保留 1500 KiB；新音频独立配置使用 2 MiB，不套旧烧录地址   |

原 LumaDesk Ding 记录中，采音和唤醒曾验证，扬声器仍存在硬件故障；不能作为新板
发声成功的证据。新板原理图/GPIO 表未提供前，不猜测引脚、不驱动未确认功放。
独立固件音频默认关闭，开启需明确确认新板引脚；`CODEPULSE_AUDIO_COMPILE_TEST`
仅检查编译，运行时禁止初始化音频 GPIO。旧板构建不启用音频。

待核实：功放型号和使能极性、供电/峰值电流、扬声器阻抗与额定功率、PDM/I2S 麦克风
型号和选声道电平、可用 GPIO、专用讲话键、走线和噪声。随后依次验证本地 PCM、
麦克风幅度、局域网语音、到期提醒及屏幕刷新时的音频/供电稳定性。

## 真实桌面文字链路（2026-10-29）

经用户明确授权，只在本机读取 LumaDesk 旧后端配置并复用通义凭据。GLM 配置中的
密钥是占位内容，未导入。原 `qwen-plus` 实际返回 HTTP 403 /
`AllocationQuota.FreeTierOnly`，表示该模型的免费额度已用完；未改动账户计费开关。
同一凭据改用 `qwen-flash` 后，以下三次真实调用均返回 HTTP 200：

- 桌面文字提问“十七加二十五”，AI 回复 `42`，不创建待办。
- 生成“联调测试：整理资料”，在真实界面确认后才写入独立测试数据库，无提醒时间。
- 自然语言“四十五秒后提醒我喝水”，生成明确的 45 秒计划；确认后等待真实系统时钟，
  由 15 秒调度器投递一次，并收到 Windows 原生通知 `show` 事件。再观察一个调度周期
  没有重复投递。操作系统显示事件不代表用户实际读过通知。

验证经过实际构建的 renderer/preload/IPC、助手 runtime、通义接口和 SQLite，未使用
AI mock、本地自然语言回退或人为推进时钟。测试配置独立，不监听生产端口、不运行
CLI hooks/采集器，不传输真实工作内容。重开测试数据库后，事项、提醒回执及加密凭据
仍存在。核对完成后仅把服务商 `tongyi`、模型 `qwen-flash` 和加密密钥保存到正式
CodePulse 用户配置，没有复制测试事项。代码没有新增对 LumaDesk 目录的运行依赖。

语音服务凭据和真实 ASR/TTS 本次不在验证范围内。此次文字联调不能代替硬件、休眠
唤醒、跨平台通知或长时间服务稳定性验收。旧模型额度问题按已知错误码给出清楚提示，
不会自动切换收费模型或更改账户计费设置。

联调后的工作区/测试类型检查、702 项回归和桌面/HUD 构建通过。新增检查覆盖免费
额度耗尽的清楚提示、超大上游错误正文的容量限制和私有错误信息不进入界面。已核对
产品源码和本地诊断输出中没有导入密钥的明文。
