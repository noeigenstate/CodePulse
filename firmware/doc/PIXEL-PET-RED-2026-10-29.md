# 像素宠物红色平面 · 2026-10-29

候选版本 `0.0.27-pet`，基于固件 `7e3d9e6` / `0.0.26-paced`。
保留默认 PAIR125、可选 PAIR150 / region 窄窗口和 ESP-IDF 6.0.1 锁定依赖。
对应版本为 `0.0.27-pet-pair150`、`0.0.27-pet-region`、
`0.0.27-pet-region-pair150`。本次仅完成软件检查，未烧录、未连接设备。

## 线上格式

`GET /api/v1/device/status` 的现有 `ambient` 对象新增可选 `red`：

```json
"red": { "x": 128, "y": 40, "w": 8, "h": 2, "hex": "0180" }
```

坐标相对于 384×208 多媒体图片区，原布局的屏幕位置为 `(8+x, 60+y)`；
0.0.28 宠物布局改为 `(8+x, 32+y)`，见下节。
`x/y/w/h` 必须是非负整数；`x/w` 是 8 的倍数，`w >= 8`、`h >= 1`，
`x+w <= 384`、`y+h <= 208`。`w*h/8 <= 3072`，`hex` 长度严格为
`w*h/4`，大小写十六进制均可，逐行、高位在前，1 表示红色颜料。
上例第一行末像素、第二行首像素为红色。128×128 宠物矩形使用 2048 字节。

只有有效 `imageHex` 图片卡允许红色。现有黑图仍为 9984 字节、19968 个 hex
字符，1 表示黑色。任何 `red` 类型、坐标、容量、长度或字符错误均只丢弃红色；
状态和黑白卡保持有效，旧红数据不会残留到新快照。没有 `imageHex` 或其为 null
时忽略红色；`imageHex` 本身不合法仍按既有严格策略拒绝整条状态。
HTTP 上限仍是 32768 字节；桌面端仍应控制整条 JSON 不超过 32000 字节。
本扩展不增加 USB、LAN 控制或配置入口，不读取或记录认证信息。

## 渲染与预览

`ambient()` 先绘制黑图，再绘制矩形中没有黑色重叠的红点；黑色优先。
反色只翻转黑白像素，红点保持红色，其黑平面位保持 1，避免黑红同时清零。
合法但全零、或被黑图完全覆盖的红色矩形不算实际红色画面。

`preview_red_frame()` 返回现有静态红平面地址，大小为 15000 字节，位清零表示
红色颜料。`preview_frame()`、`preview_size()`、`preview_render()` 的黑平面接口不变；
预览显示目标像素，不模拟硬件冷却和刷新。Wasm manifest 格式保持不变。
native 适配器保留原黑平面输出文件和传感器参数，可选在参数末尾追加红平面输出路径。

## 宠物布局（0.0.28）

2026-10-30 候选 `0.0.28-pet` 基于 `f5e21fd`，各 PAIR150 / region 后缀不变。
在现有 `ambient` 对象中增加可选字符串 `"layout": "pet"`，只随有效 `imageHex`
发送；桌面端仅宠物卡设置。只有精确的 `"pet"` 且有图片时启用新布局。
缺省、null、未知字符串、数字、对象、数组、布尔值或没有图片时均回到原布局，
任何非法 `layout` 都不会使整条 status 解析失败；图片本身仍按既有严格规则校验。
新快照会清除前一快照的布局选择。旧固件（≤0.0.27）忽略该字段，沿用原布局，
无需版本协商。此字段不改变图片编码、红色矩形容量或预览导出接口。

| 区域 | 坐标 / 基线 | 内容 |
| --- | --- | --- |
| 页眉 | y=0–30，分割线 y=30 | 沿用原页眉 |
| 黑色图片 / 红色矩形原点 | (8,32)，384×208，覆盖 y=32–239 | 红色坐标仍相对于图片 |
| 分割线 | x=12–387，y=243 | 1 像素黑线 |
| 台词 `text` | x=12，宽376，基线 y=270，单行 | `DISPLAY_TITLE`，20px/700 |
| 超宽台词 | x=12，宽376，基线 y=266，单行 | `DISPLAY_META`，12px/500 |
| 来源 `source` | x=12，宽376，基线 y=293，单行 | `DISPLAY_META`，12px/500 |

以 `display_font_width(DISPLAY_TITLE, text) > 376` 决定回退；等于376仍用20px。
回退后仍超宽时沿用既有 UTF-8 安全省略规则，不新增换行、缩放或抗锯齿。
无 `layout` 的图片卡及所有无图片卡保持原像素。黑色优先、反色、红色折为当前
前景墨色、全刷选择及120秒冷却均保持原规则，只移动红色像素的图片原点。

`scripts/test-host.ps1` 覆盖36个布局解析组合及非法图片仍严格拒绝；
`scripts/test-quiet.ps1` 增加图片边界、页眉、分割线、字号/基线、来源字库、
逐字符覆盖、回退、反色、红点原点/重叠与冷却检查。`preview/test-preview.mjs` 保留旧用例，
新增宠物布局的 native/Wasm 黑红双平面对照。
`preview/check-legacy.mjs` 使用从 `f5e21fd` 独立构建得到的旧 fixtures，逐字节
比较65个黑白及11个红色用例的两平面。`preview/render-pets.mjs` 可只读加载桌面
宠物绘图模块，用新 Wasm 输出15张400×300 PNG和一张2000×900总览。

实际量宽的15句宠物台词为200–300px，全部使用20px，无截断。
字形比较按实际 atlas 中非回退的记录统计，包含 U+FFFD；每种字体均有7752个码位槽。
`DISPLAY_TITLE`（20px/700）与 `DISPLAY_META`（12px/500）各有7752个有效字形，
其中汉字6763个，覆盖集合完全相同。`DISPLAY_STATE`（14px/500）仅128个有效字形、
32个汉字，比 META 少7624个码位；`DISPLAY_SUMMARY` 也只有同样的固定词汇覆盖。
因此按主会话返工约定，来源及台词回退均改用 META；字库和生成器保持不变。
TITLE 相对 META 无覆盖缺口，无需额外运行时缺字选择逻辑；两者仍以 U+FFFD
处理既有7752码位范围之外的字符。测试复用生产字形查找，核对全部码位集合及
15句台词、3个来源在最终字体中的逐字符覆盖，并验证非固定词汇中文的12px回退。

本机无 ESP-IDF，仅完成软件构建/检查，不宣称 ESP32-S3 目标编译、分区余量或
实机可读性已验收；未烧录、未访问设备，供电、联网与刷新结果均待实机验证。

## 刷新决策

更新函数接收调用方提供的 `int64_t now_ms`。应用层沿用
`esp_timer_get_time()/1000` 单调时间，渲染层不读取时钟。
状态新增 `previous_has_red`、`red_checksum`、`has_runtime_full` 和 `last_full_ms`；
保留原有最后成功黑平面，不另存 15000 字节的上一红平面。
红校验采用无查表的 32 位 FNV-1a，覆盖全部 15000 字节；黑平面继续逐行精确比较。
校验有理论碰撞可能，不将它视为红平面的逐字节历史副本。

| 最后成功画面 | 本次目标 | 像素变化后采用的路径 |
| --- | --- | --- |
| 未初始化 | 任意 | 原开机 OTP 全刷，日志 `clean_baseline` |
| 无红 | 无红 | 原单个包围横带的 PAIR 低闪更新 |
| 无红 | 有红，允许进入 | 三色全刷，真实红平面，日志 `red_full` |
| 无红 | 有红，进入冷却中 | 红点按当前模式的墨色显示，清空红平面，再比较黑白画面并低闪更新 |
| 有红 | 有红或无红 | 三色全刷，替换或清除实际红色，日志 `red_full` |

两平面都没变时没有面板调用。只改变红点、黑平面不变也会被红校验识别。
运行时全刷直接复用 `epd_ssd1683_refresh()`，成功后该驱动恢复有效低闪基线。
离开红色时上传全 0xFF 红平面；后续 PAIR 使用这次全刷的成功黑平面作为 OLD。
低闪驱动原有“红平面非 0xFF 则拒绝”的保护继续有效。

**进入红色受 120 秒冷却限制，离开不限制**：成功的运行时全刷后，记录
`last_full_ms = now_ms + timing.total_ms` 作为完成时间，
下一次无红→有红在差值 `< 120000` 时折为墨色，恰好 120000 时允许进入。
时间早于记录的完成时间也视为冷却中。开机清洁不消耗运行时冷却；
未变化、低闪更新和失败不会推进这条成功时间。
已有红色时的替换、反色、黑图变化或离开必须全刷，不受冷却限制。

折色发生在最终渲染之后：普通模式红点折为黑墨（黑位 0），反色模式折为白墨
（黑位 1），两种模式都清空红平面（红位 1）。状态保存实际下发的画面，
不会把墨色降级误记成已显示红色。冷却到期不新增定时刷新：保留原有 ambient ID
冻结策略；同卡停留期间不受后台工作、额度和环境变化驱动，后续明确更新才重新决策。
桌面继续负责固定卡片 ID、自动推送间隔、每日次数、安静时段和空闲门槛。

红色卡片显示时若遇到紧急提醒，离开红色必须用三色全刷清红，预计提醒出现需要
约 16 秒，而黑白低闪更新约 3 秒。在这次同步全刷期间，长按关机也要等刷新安全
结束才处理，等待量级同样从约 3 秒增加到约 16 秒。以上为既有波形的参考耗时，
本候选未实机验证；按键检测与安全关机顺序保持不变。

## 失败处理

三色全刷与低闪错误共用原故障路径：驱动保留有界 BUSY 等待和面板关断；
更新器标记 `faulted`，不推进黑平面、红校验、实际红色标志或成功时间；
后续更新返回 `ESP_ERR_INVALID_STATE`。应用层记录失败并调用原
`shutdown_safely()` 释放供电，不自动重试、复位或回退追加全刷。
没有修改 LUT、波形、开机清屏、GPIO9 保持供电、按键或关机顺序。
