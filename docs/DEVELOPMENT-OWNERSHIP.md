# 产品与嵌入式协作约定

本约定建立于 2026-10-24。产品功能会话负责整体产品定位、设计和功能开发；
嵌入式会话负责固件与硬件实现、刷新策略、烧录和实机验证。两者维护同一个
CodePulse 产品，使用两个独立 Git 仓库。

## 先读与工作入口

开始工作前依次阅读：

1. `AGENTS.md`：当前仓库的执行约定。
2. 本文：职责、仓库与跨端协作规则。
3. [WORKSPACE.md](WORKSPACE.md)：构建、启动与运行数据的位置。
4. [UNIFIED-PRODUCT.md](UNIFIED-PRODUCT.md)：统一整合的来源、验证和限制。
5. 涉及设备时再读 [device-api-v1.md](device-api-v1.md)，并核对独立固件仓库
   的 `README.md`、`AGENTS.md`、`doc/DEVELOPMENT.md` 和实际实现。

以当前工作目录内的分支、文件和 Git 状态为准，不沿用旧会话记忆中的双目录启动方式。

## 职责与文件归属

| 范围 | 主要负责方 | 实现位置 |
| --- | --- | --- |

| ESP-IDF、板级引脚、电源保持、USB、Wi-Fi、传感器、屏幕驱动 | 嵌入式会话 | 独立固件仓库 |
| 实体屏版式、字体栅格、刷新波形、时序、残影控制 | 嵌入式会话按产品设计实现 | 固件 C 渲染器与驱动 |
| 固件编译、烧录、版本追溯、现场/家庭测试包与反馈 | 嵌入式会话 | 固件仓库及私有测试资料 |

产品功能会话可以正常推进桌面功能，无需等待无关的硬件测试。涉及新屏幕布局、
字体或显示能力时，先写清目标与验收示例，由嵌入式侧实现生产渲染器，再同步预览。
桌面设计稿可以先探索，但不能把另写的 HTML/CSS 示意图当成实体屏已支持的画面。

## 仓库、分支与远端

产品代码统一管理在 `https://github.com/noeigenstate/CodePulse.git` 的
`codex/unified-product` 实验分支。标准桌面、HUD 与墨水屏配置预览已经同仓，
该分支可单独克隆、构建和运行。不要再向旧 `CodePulse-HUD` 仓库持续开发或发布。

本约定建立时，已推送的整合基线是 `6d08691`；主要整合代码是 `7eb6457`。
这些是历史定位点，开始新工作时仍应检查当前 HEAD，不要将分支重置到它们。
`main` 尚未合入这些功能。没有明确授权，不合并 main、不强推、不发布安装包。
已经获得的操作授权继续有效，不因本文件要求重复确认。

远端名字不能代替地址校验：本机继承的 Git 配置中，`origin` 可能仍是旧 HUD 仓库，
而 `upstream` 才是 CodePulse 主库；新克隆中通常恰好相反。提交前检查工作树和分支，
推送前确认完整地址与目标分支，使用明确 refspec。例如，在已核对 `upstream`
就是主库且用户已授权推送时：

```powershell
git status --short
git branch --show-current
git remote -v
git remote get-url upstream
git push upstream HEAD:refs/heads/codex/unified-product
```

固件仓库独立提交、独立版本和独立远端。不要把固件源码、烧录包或私有硬件资料
塞进公开产品仓库，也不要把桌面变更提交到固件仓库。构建桌面不要求固件仓库访问权限。

旧的 HUD 与标准宿主工作区保留用于溯源和回退；其中可有已迁入统一分支但仍显示
未提交的历史改动。不能据此再次整目录覆盖统一分支，也不能为了“清理”直接 reset、
clean 或删除。先按文件或提交核对，保留后来产生的真实新增工作。

## 并行开发与跨仓变更

- 产品侧默认写统一产品工作区；嵌入式侧默认写固件工作区。
- 一方需要修改对方负责的文件时，先在交接记录中说明文件、目的和当前基线，
  避免两个会话同时写同一文件。需要隔离时使用单独工作树或临时分支，完成后审查差异。
- 不用 Git stash、reset、批量复制来消除不属于自己的改动；提交只包含本次负责的内容。
- 协议新增字段优先保持兼容，明确缺省值、未知值、旧固件行为和容量限制。
  破坏兼容的改动需明确版本和迁移办法。
- 发布记录同时写出产品 commit、固件 commit、固件版本和预览 manifest；不要用一个
  仓库的提交号冒充整套系统版本。区分“代码完成”“已构建”“已刷入”和“实机通过”。

跨端交接至少包含：需求与验收标准、各端基线、修改文件、协议/配置变化及兼容性、
真实 400×300 样例、预期刷新范围、完成的检查、未完成的实测、产物位置与下一步负责方。
含设备身份或网络信息的附件放在私有本地记录中，公开文档只保留可公开的结论。

## 预览与低闪策略

标准桌面和 HUD 的设备配置使用同一生产 C/Wasm 渲染器。以下两处资产必须保持一致：

- `apps/desktop/src/renderer/src/device-preview`
- `apps/hud/src/renderer/src/device-preview`

固件版式或字体变化后，嵌入式侧提供核验过的 Wasm、base64、manifest 和必要的
适配/许可变更；产品侧接入并验证。已有同步脚本会同时更新两处 Wasm、base64 和
manifest，适配器或许可有变化时也要成对更新。随后运行构建及像素一致性检查。

保持已接受的布局、卡片稳定性和低闪行为，除非用户提出相应变更。温湿度小幅变化
不单独触发刷新；任务和配置及时下发，不重新引入历史三分钟等待规则。物理刷新
时序、波形和清屏决策归固件实现，不能仅靠桌面预览证明效果。

当前预览表达目标像素，不是设备刷新回执；它不模拟残影和闪烁。设备遥测未回传时
显示未知值，不伪造温湿度、电量或联网状态，也不宣称预览与实体屏已同步完成。

## 启动与验证

在统一产品仓库根目录执行：

```powershell
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
pnpm --filter @codepulse/desktop rebuild:electron
pnpm test:surfaces
```

`pnpm test` 使用 Node 的 SQLite ABI；运行 Electron 前需要恢复 Electron ABI。
隔离窗口测试使用合成数据和独立配置，不接管真实任务。根据改动选择相关检查，
文档修改不需要反复重跑完整测试。

正常启动使用 `pnpm start`；Windows 需要 LAN 设备服务时使用
`scripts/start-desktop.ps1 -Build -DeviceServer`。只运行一个 CodePulse 后台：
标准桌面、HUD、屏幕工作台共享 StatusHub、hooks、采集服务和设备 API。
端口 17888 被占用时先确认现有实例，不能直接杀进程或另起一个 HUD 后台。

切换开发版本只处理 CodePulse 自身，不终止、重启或重配正在工作的 Codex/ChatGPT
任务。在生产实例运行时，用独立依赖目录做测试，避免改写它正在使用的原生模块。
