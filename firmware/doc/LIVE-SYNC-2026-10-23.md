# 0.0.18 即时同步 — 2026-10-23

## 目的与实现

用户要求 CodePulse 提醒及时出现，取消已经不适用的分钟级等待，保持当前布局
和已验收的 PAIR125 低闪波形。实现详见桌面 [设备协议](../../docs/device-api-v1.md)。

- 桌面新增带 ETag 的认证条件等待，最多保持 1 秒；状态事件、已保存配置主动
  唤醒等待的请求。设备持续读取，取消 30 秒取数间隔，缓存已验证备用地址。
- 重要提醒优先分类；普通状态、列表／标题、额度、模式同样立即符合刷新条件。
  删掉 60 秒稳定期、180 秒显示门槛及手动刷新重复门槛。
- 刷新期间不并发驱动，结束后读取最新快照；不回放已过时中间态。工具详情噪声、
  相同画面以及小幅环境变化不触发波形。大环境变化／电量规则保留。
- 仍只有启动清洁一次，运行中继续 PAIR125 变化横带；出错停止，无自动全刷补救。
  没有改字体／布局、三档字号、图标、3／6／9 规则、颜色、NVS、SDK或分区。

主任务中的条件请求最长正常保持 1 秒，留出按键检查机会。网络故障仍存在
连接／请求超时与重试；“即时”描述在线桌面已经采集到状态后的正常传输和调度，
不是对断网、桌面进程繁忙或数据源本身延迟的硬实时保证。

## 追加验收结果：快速同步通过，残影未通过

17:03:19 与 17:04:34 两次待处理提醒在桌面与设备日志中出现在同一秒，说明
分钟级等待已经移除。但前两次局刷约 2.64 秒之后，后续多次驱动稳定在约
5.25–5.27 秒；仍是一次 PAIR125 横带更新，ESP_OK，无运行中全刷回退。
用户确认闪烁过程仍舒适，但残影明显过重。因此 0.0.18 不能记作光学验收通过。

检查发现屏幕复位低电平用 vTaskDelay(pdMS_TO_TICKS(5))，实际 sdkconfig 为
CONFIG_FREERTOS_HZ=100；ESP-IDF 自带的整除宏将其算成 0，只让出执行权，
无法保证原意中的 5 ms 低脉冲。这个软件时序错误已确认；它是否导致驱动耗时
翻倍和残影加重尚未证实，需与 0.0.19 实机对比。重复局刷本身也可能累积残影，
此前少量、长间隔往返测试不能替代连续真实任务的光学验收。

另修正设备投影分组：同一工作目录的 Windows 路径和 file URI 归一到相同组，
避免表示形式变化导致卡片换位。仅影响设备表现层，不修改 StatusHub、任务身份
或 HUD 自身排序。新增原生路径／转义 URI／localhost／UNC 回归，桌面总计
51 项通过。无新增分钟级门槛、自动清洁全刷或设备数据回传。
