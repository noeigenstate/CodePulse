# WFT0420CZ15 手动横带局刷实验

这是独立编译的 `0.0.3-window-probe`，不是已经验证的功能。
普通构建默认关闭 `CODEPULSE_EPD_WINDOW_PROBE`，仍为 `0.0.3-smart-refresh`。

## 实验目的与边界

验证原 OTP 三色模式下，400×40 的全宽横带能否独立刷新，以及横带外的黑白、红色是否受到扰动。全宽窗口避免在屏幕中间设置横向边界，但并不保证绕过已知控制器问题。结果可能仍是全屏闪烁、失真或无更新。

仅使用原 OTP 三色波形，增加 `0x90/0x91/0x92` 窗口命令；不加载黑白自定义 LUT、不改驱动电压、不写 OTP。保留 GPIO9 优先保持供电、GPIO42/GPIO8 输入、30 秒 BUSY 上限和刷新后高压关闭。

此构建停用 Wi-Fi 同步和 USB 配网服务，不读取或修改 NVS 配网数据。它暂时替代日常看板，只用于目视实验；测试后需刷回普通构建。串口只有诊断日志，不能用 CP1 探针验收这个实验版本。

## 手动流程

1. 按既有刷写流程持续按住功能/电源键，刷入实验应用；完全松开掉电，再长按约 3 秒正常启动并松开。
2. 启动只执行一次原有全刷，显示 `AGENT WAIT`、横带边界与上下红/黑对照标记。
3. 从刷新结束起至少等 180 秒。短按一次，执行唯一一次横带实验，目标内容为 `AGENT RUN`。提前按只记录冷却剩余时间，不排队触发。
4. 观察：是否只有两条横线之间的横带闪烁；上部、底部和右侧的黑色、红色是否保持；`WAIT` 是否变成 `RUN`；横带内静态红字是否正确。串口成功只说明 BUSY/通信完成，不能证明视觉通过。
5. 再等至少 180 秒，短按执行一次原始全刷恢复到 WAIT。无论窗口成功或失败，都不会自动重试窗口。之后任何短按均不再刷新。
6. 长按约 3 秒关机，刷新中收到的长按在安全结束后执行。最终刷回普通固件并验证配网、Wi-Fi 同步。

没有周期性物理刷新。正常实验最多三次波形：初始全刷、手动窗口、手动恢复全刷。没有试验过的玻璃批次，不能把这份代码直接当作产品局刷驱动。

## 构建隔离

从统一桌面仓库执行，复用既有 SDK 配置的独立副本。构建目录和日志放在忽略目录 `.tmpshots`，不要覆盖普通 `firmware/build`。

```powershell
. '..\firmware\scripts\idf-env.ps1'
Copy-Item '..\firmware\sdkconfig' '.tmpshots\window-probe-sdkconfig'
& $IdfPython (Join-Path $env:IDF_PATH 'tools\idf.py') `
  -C '<checkout>irmware' `
  -B '<checkout>\.tmpshots\window-probe-build' `
  -D CODEPULSE_EPD_WINDOW_PROBE=ON `
  -D SDKCONFIG=<checkout>/.tmpshots/window-probe-sdkconfig build
```

刷写前确认普通固件与实验构建分区表一致，并保留可刷回的普通应用镜像。串口需要独占；刷写仍需用户实际按住功能/电源键，禁止自动刷写或自动复位。当前通用 `scripts/flash.ps1` 固定使用普通 `build/`，不能用它刷实验镜像。

相关证据：[面板刷新调查](../../doc/PANEL-REFRESH-INVESTIGATION-2026-10-20.md)。
