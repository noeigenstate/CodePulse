## 目标与触发条件

每 30 秒等待后取数，网络请求耗时另计。每次成功刷新保存实际显示的模型，
后续始终与该模型比较；不会把上次轮询的数据当成屏幕已经显示的内容。

| 变化 | 自动刷新条件 |
| --- | --- |
| agent 状态 | 相对屏幕发生变化，且同一 agent 的新状态持续至少 60 秒 |
| 额度 | 屏幕实际显示的整数百分比改变，包括未知与已知互换 |
| 网络可达性 | 新连接状态持续至少 60 秒 |
| 温湿度小变化 | 不独立触发；在其他刷新时顺带更新 |
| 温湿度大变化 | 相对屏幕累计至少 1°C 或 5 个湿度百分点，且距成功刷新至少 15 分钟 |
| 电量小变化 | 不独立触发；在其他刷新时顺带更新 |
| 电量大变化 | 相对屏幕累计至少 10 个百分点，或采样有效性变化，且至少间隔 15 分钟 |
| 传感器有效性变化 | 与温湿度大变化同样采用 15 分钟间隔 |
| 全刷失败 | 保留最后成功的模型，标记屏幕不确定，冷却后重试 |

所有自动刷新还要满足：距上次刷新尝试完成至少 **180 秒**。
因此连续变化会合并，一次全刷显示最新 agent、额度、温湿度、电量和联网标记。
没有达到条件时，即使位图或 API revision 改变也不发起刷新。

状态稳定时间按 agent 独立计算。一个 agent 抖动不会使另一个持续状态无限等待，
额度更新也不会重置状态计时。短暂 WAIT/RUN 往返在轮询到恢复后取消等待。
同类运行状态已在协议解析时映射到同一个 RUNNING 显示状态。

仅比较屏幕上的字段：Claude 为 5H 与 WEEK，Codex/Grok 为 WEEK。
未绘制的 5H、Token 总数、上下文、项目、模型或时间戳不会单独触发全刷。
首次开机、配网应用和短按仍立即刷新全部内容，并在成功后更新比较基线。

## 局部刷新边界

本机仍使用已验证的 WFT0420CZ15 legacy 黑白红全刷波形。小区域的内容改变，
不等于面板有可靠的无闪局刷能力。厂商的
[4.2inch e-Paper (B) 选型表](https://www.waveshare.com/product/4.2inch-e-paper-b.htm)
没有标注局刷支持；[官方说明](https://www.waveshare.com/wiki/4.2inch_e-Paper_Module_%28B%29_Manual)
要求以具体型号能力为准。当前驱动没有经过验证的局刷/LUT 实现。

本次只减少何时发起全刷，不改变显示波形、BUSY 等待、电源关断或颜色布局。
以后如实验局刷，应单独核实面板/控制器版本、红色层保持与残影；不能只裁剪
SPI 写入区域就称为已经消除全屏闪烁。

2026-10-20 已进一步核实同排线面板和 UC8176/IL0398 三色局部窗口的已知问题。
目前没有找到经验证的低干扰快刷实现；准确结论、证据强度及黑白模式边界见
[面板刷新调查](PANEL-REFRESH-INVESTIGATION-2026-10-20.md)。本次没有修改波形或刷写固件。

## 验证入口

`scripts/test-host.ps1` 编译实际 C 协议解析器和刷新策略，覆盖：小幅波动抑制、
累计阈值、独立状态防抖、可见额度、冷却边界、失败后的显示基线、网络状态、
agent 顺序及手动刷新基线。`scripts/build.ps1` 做 ESP-IDF 6.0.1 目标编译。
物理刷新频率和显示效果需在刷入后另做真机检查。

## 横带实验新证据（2026-10-20）

独立实验 `0.0.3-window-probe` 的 400×40 全宽窗口 / PT_SCAN=0 已完成一次
原 OTP 三色刷新：15,834 ms、ESP_OK，用户确认仅横带闪烁且 WAIT→RUN，
窗口外稳定。这修正了“任何更新都必然整屏闪烁”的判断；仍不是无闪快刷，
普通 `0.0.3-smart-refresh` 尚未集成窗口更新。其他位置/高度、长期残影与
红色变化需继续验证。证据和恢复状态见调查及实验 README。
